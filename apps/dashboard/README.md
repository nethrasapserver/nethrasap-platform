# Nethrasap Dashboard

Next.js 14 App Router dashboard for Nethrasap — covers admin, manager, sales, HR, and user portals (~60 routes).

## Stack
- Next.js 14.2 (App Router)
- React 18.3
- TypeScript 5.5
- Global CSS (legacy stylesheets ported from the original Babel-in-browser prototype)

## Getting started
```bash
npm install
npm run dev        # http://localhost:3000  → redirects to /login
npm run build      # production build
npm start          # serve the production build
```

## Project layout
```
app/                Route segments. Each <route>/page.tsx is a thin client-only
                    wrapper that mounts a component from components/legacy.tsx.
components/
  legacy.tsx        Single client module containing every page + shared shell
                    component. Auto-generated by concatenating the original
                    shell.jsx + portal-shell.jsx + product-card.jsx +
                    chatbot.jsx + *-pages.jsx, with `'use client'` and proper
                    React imports prepended.
  ClientOnly.tsx    Mount-gated wrapper used by every route page so the legacy
                    components (which read window.NETHRA_DATA at render) never
                    execute during SSR.
lib/
  icons.tsx         Inline SVG icon set (ported from legacy icons.js).
  images.ts         Unsplash URL builders (ported from legacy images.js).
public/legacy/
  data.js           Mock dataset — populates window.NETHRA_DATA via IIFE.
  data-portal.js    Portal-specific mock data — populates window.NETHRA_PORTAL.
  tooltips.js       Tooltip behavior, attached on document load.
styles/             Global stylesheets, imported in app/layout.tsx.
types/globals.d.ts  Ambient typings for the window globals above.
```

## Route map
Flat naming mirrors the original HTML filenames:
- Auth: `/login`, `/signup`, `/forgot-password`
- User account: `/dashboard`, `/profile`, `/addresses`, `/my-orders`, `/order-detail`, `/my-enquiries`, `/enquiry-detail`, `/my-notifications`
- Admin portal: `/admin-dashboard`, `/admin-analytics`, `/admin-products`, `/admin-product-new`, `/admin-product-edit`, `/admin-categories`, `/admin-inventory`, `/admin-orders`, `/admin-order-detail`, `/admin-enquiries`, `/admin-enquiry-detail`, `/admin-users`, `/admin-roles`, `/admin-cms`, `/admin-page-editor`, `/admin-notifications`, `/admin-settings`
- Manager portal: `/manager-dashboard`, `/manager-analytics`, `/manager-performance`, `/manager-orders`, `/manager-enquiries`, `/manager-enquiry-detail`, `/manager-verifications`, `/manager-team`, `/manager-notifications`, `/manager-settings`
- Sales portal: `/sales-dashboard`, `/sales-reports`, `/sales-products`, `/sales-orders`, `/sales-order-detail`, `/sales-enquiries`, `/sales-enquiry-detail`, `/sales-team`, `/sales-notifications`, `/customers`
- HR portal: `/hr-employees`, `/hr-attendance`, `/hr-leave`, `/hr-holidays`, `/hr-payroll`
- Verifications: `/verifications`, `/verification-detail`
- Legal: `/privacy`, `/terms`, `/refund`
- System: `/offline`, plus Next.js conventional `not-found.tsx` & `error.tsx`

## Migration notes
- `next.config.mjs` sets `typescript.ignoreBuildErrors: true` and
  `eslint.ignoreDuringBuilds: true` because `components/legacy.tsx` was
  auto-generated from untyped browser-Babel JSX. Hand-written files (lib/,
  components/ClientOnly.tsx, app/) still get checked via `npm run typecheck`.
- Inter-page hrefs were rewritten from `*.html` to `/route` paths. Plain
  `<a href="/route">` is preserved — swap to `next/link` route-by-route as
  pages are individually polished.
- `Object.assign(window, ...)` and `window.X = X` statements in the bundle are
  still kept (guarded by `typeof window !== "undefined"`) because some
  components read each other via globals. Replacing them with proper imports
  is the next refactor step.
- The customer storefront (home, products, cart, checkout, etc.) was removed
  in an earlier cleanup — `/` redirects to `/login`.
