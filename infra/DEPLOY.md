# Deploying Nethrasap

Topology at launch:

| Component | Where | Notes |
|---|---|---|
| API + WebSocket hub | **Render** web service (Docker) | from `render.yaml` |
| Background worker (arq) | **Render** worker (same image) | SMS, PDFs, payroll, webhooks |
| Redis | **Render Key Value** | pub/sub + queue + rate limits |
| PostgreSQL 16 | **Neon** (external) | already provisioned |
| Storefront + Dashboard | **Cloudflare Pages** | done last (see bottom) |
| Object storage | **Cloudflare R2** | done last |

The whole backend is one blueprint. Migrations and the RBAC seed run
automatically on every deploy (pre-deploy hook), so a deploy is one click after
the initial setup.

---

## 1. Prerequisites

- GitHub repo pushed (done): `github.com/nethrasapserver/nethrasap-platform`.
- A **Neon** Postgres project. Copy its **pooled** connection string, e.g.
  `postgresql://USER:PASS@ep-xxx-pooler.REGION.aws.neon.tech/neondb?sslmode=require`.
- A Render account.

## 2. Create the blueprint on Render

1. Render Dashboard → **New +** → **Blueprint**.
2. Connect the GitHub account and pick **nethrasap-platform**.
3. Render reads `render.yaml` and shows: `nethrasap-api`, `nethrasap-worker`,
   `nethrasap-redis`, and the `nethrasap-shared` env group. Click **Apply**.
4. Render will prompt for the `sync: false` env vars (see §3). At minimum you
   must provide **DATABASE_URL** for the first deploy to succeed.

## 3. Environment variables

Set on the **`nethrasap-shared`** env group unless noted. `JWT_SECRET` is
generated automatically; everything else marked "required now" you must enter.

| Variable | Required now? | Value |
|---|---|---|
| `DATABASE_URL` | **Yes** | Neon pooled connection string |
| `JWT_SECRET` | auto | generated by Render (shared api+worker) |
| `ENVIRONMENT` | preset | `production` |
| `REDIS_URL` | auto | wired from the Render Key Value service |
| `CORS_ORIGINS` | later | comma-separated frontend origins (set when Cloudflare Pages URLs exist) |
| `SMS_PROVIDER` | preset | `console` (OTPs print to worker/api logs) until a real provider |
| `SMS_API_KEY` / `SMS_SENDER_ID` | later | when you pick MSG91/Exotel/Twilio |
| `STORAGE_*` | later | Cloudflare R2 endpoint + keys (KYC docs, invoice/payslip PDFs) |
| `RAZORPAY_KEY_ID` / `_SECRET` / `_WEBHOOK_SECRET` | later | test keys first, live keys at go-live |

Until R2 / Razorpay / SMS are set, those integrations run on their built-in
stubs — the app is fully functional, files aren't stored and payments aren't
charged. Flipping them on is **env-only**, no redeploy of code.

> **Production safety:** the app refuses to boot with a placeholder or <32-char
> `JWT_SECRET` when `ENVIRONMENT != dev`. Render's generated secret satisfies this.

## 4. What happens on deploy

The API service's **pre-deploy command** runs against the new image before it
takes traffic:

```
alembic upgrade head && python -m scripts.seed_rbac
```

- `alembic upgrade head` applies any pending migrations (0001–0010) to Neon.
- `scripts.seed_rbac` upserts the 6 roles + permission grants (idempotent —
  safe on every deploy; picks up new permissions automatically).

No demo users or catalogue are seeded in production. Create the first admin and
products through the API/dashboard, or run `scripts.seed_dev` manually against a
staging DB only.

## 5. Post-deploy checks

```
curl https://nethrasap-api.onrender.com/api/v1/health   # {"status":"ok"}
curl https://nethrasap-api.onrender.com/api/v1/ready     # {"status":"ready"} — DB reachable
open  https://nethrasap-api.onrender.com/docs            # interactive API
```

WebSockets work on Render web services natively (the `/api/v1/ws` hub needs no
extra config). The worker service has no public URL — check its **Logs** to
confirm `worker.startup`.

## 6. First admin user

There is no seeded admin in production. To bootstrap one, either:
- temporarily run `scripts.seed_dev` against the DB (creates demo staff incl.
  admin `+919800000006` / `Demo123!`) then change the password, **or**
- insert an admin `users` row + profile directly and set its password hash.

Prefer the first for convenience on a fresh DB; rotate the demo password
immediately.

## 7. Frontends (Cloudflare — later)

The two Next.js apps deploy to **Cloudflare Pages** with
`@cloudflare/next-on-pages` (root dirs `apps/storefront` and `apps/dashboard`).
Build-time env: `NEXT_PUBLIC_API_BASE=https://nethrasap-api.onrender.com` (add
API base support to the client) or keep the Next rewrite proxy. Then set the
API's `CORS_ORIGINS` to the Pages domains. R2 buckets (KYC/invoices/payslips)
are created in the Cloudflare dashboard and their keys go into the `STORAGE_*`
env vars.

If Pages' `next-on-pages` limits bite, the fallback is deploying the two apps as
additional Render web services (Docker, `infra/Dockerfile.frontend`,
`--build-arg APP=storefront|dashboard`) — everything else is unchanged.
